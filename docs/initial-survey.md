## 3. 텍스트 종류

### 3.1 정적 조사

- **평문 Shift-JIS 대사: 발견 못 함.** 추출한 파일 484개(AIF 제외)를 히라가나·가타카나 비율로 걸렀을 때 의미 있는 문장은 `TVSP.MSX`(개발자 메모, 게임 화면에 쓰이는지 미확인)뿐이었다. 메인 실행 파일 `0`에도 없음.

### 3.3 음성 분량 (확인: AIFF COMM 헤더 합산)

AIFF 665개, 합계 약 166분. 이 가운데 `STP/STL/STC/STM/YKM` 94개가 약 103분이고, 쓰임새(음성 드라마, 음악 등)는 아직 확인하지 않았다. 나머지 캐릭터별 짧은 음성(`A/B/D/H/Q/T/O/P/V/W/Y…` 접두)이 약 30분, 이야기 장면 스트림(`2SUTI`~`8ALL`)이 약 28분이다. 음성에 대응하는 대본 텍스트는 디스크에서 찾지 못했다.

### 3.4 그림 글자의 저장 방식 (확인)

세이브 스테이트의 VDP1 VRAM(16비트 리틀엔디언으로 저장됨)과 CRAM에서 명령 목록을 따라가 화면에 그려진 스프라이트를 모두 꺼내고, 텍스처 바이트 **전체**를 디스크 파일에서 찾았다.

| 화면 | 글자 스프라이트 원본 | 형식 |
|---|---|---|
| 메뉴, 난이도, 사운드 테스트, 스테이지 선택, 파트너 선택 버튼 | `SELECT1.BIN` (예: メニュー `@0x4cdc` 120×32, パートナーセレクト `@0x545c` 176×32, 곡 제목 `@0xfcdc` 160×56) | 4bpp 팔레트 뱅크, 비압축, 파일 안에 한 번만 있음 |
| 상대 소개 카드 (1스테이지) | `APRUMI.BIN @0x51044` 112×56 | 4bpp, 비압축 |
| 대국 화면 (東場/一局, VS, 이름, 南, 점수 숫자, 패) | 스테이지 오버레이 `RUMI.BIN` 등 13개(`ALICE/TUKASA/SANAE/RUMI/YUKI/SIHO/SESIL/SESIL2/HIMITU/NAZO/SECRET/HIDDEN/KAKUSHI.BIN`)에 같은 위치로 한 벌씩 (예: 留美 `@0xa9cdc` 48×16, 東場 `@0xa887c` 48×32) | 4bpp, 비압축 |
| 타이틀 (로고, Ⅱ, アイドル雀士, 最初から/続きから始める, PRESS START, 저작권 표기) | `PROLOG.BIN @0x7900` LZSS 압축 블록 안의 "Yc" 스프라이트 묶음 (3.6절) | 4bpp, **압축** |

- 스테이지 파일(1MB)은 Low 작업 RAM(`0x00200000`~)에 통째로 올라가는 오버레이 이미지다(1스테이지 대국 중 WorkRAM-L과 `RUMI.BIN`이 64KB 단위로 일치).
- 텍스처는 헤더 없이 연달아 붙어 있고, 텍스처 주소를 모은 표는 아직 찾지 못했다(VRAM 배치를 코드가 정하는 것으로 보임). 같은 크기로 제자리에 바꾸는 방식에는 이 표가 필요 없다.
- 4bpp 글자의 색 번호 예(留美): 5 = 바깥 테두리, 4 = 안쪽 테두리, 1~3 = 채움 그라데이션, 0 = 투명.

### 3.5 대표 PoC: 대국 화면 이름 교체 (통과)

- 변경: `RUMI.BIN` 오프셋 `0xa9cdc`의 48×16 4bpp 텍스처(384바이트)를 같은 크기의 "루미"(나눔고딕 ExtraBold 13px, 색 번호 2/4/5)로 교체.
- 디스크 반영: 파일 LBA 262191 + 오프셋 → 섹터 262530 한 개. 쓰기 전에 원본 바이트 일치를 확인하고, Mode 1 EDC/ECC를 다시 계산했다. EDC/ECC 계산기는 원본 섹터 110개에서 원본과 같은 값을 내는 것을 먼저 확인했다. 원본과 비교한 차이는 섹터 262530 안의 556바이트뿐.
- 결과: Mednafen으로 PoC 디스크를 부팅해 1스테이지 대국에 들어가자 이름 칸에 "루미"가 원래 팔레트 그대로 표시됨(`work/evidence/poc-name-before-after.png`).
- 이 PoC가 보여 주는 범위: 비압축 4bpp 스프라이트는 파일 크기·위치를 바꾸지 않고 제자리 교체로 화면에 반영된다. 파일 시스템·적재 코드 변경은 필요 없다. 보여 주지 않는 범위: 압축된 그림(타이틀 등), 원래보다 큰 그림, 스테이지 오버레이 13개 중 `RUMI.BIN` 이외 파일의 소비 경로.

### 3.6 타이틀 그래픽 추적 (확인)

- **적재 경로:** 오프닝 중에 `PROLOG.BIN`(1MB)이 WorkRAM-L `0x00200000`에 통째로 올라와 있고, Start를 누르면 CD 읽기 없이 곧바로 타이틀 스프라이트가 VDP1 VRAM에 나타난다. 오프닝 중(pre)부터 Start 직후까지 세이브 스테이트 17개를 연속으로 찍어 확인했다(`work/trace/title/`). 타이틀 이후 상태만으로는 원본을 알 수 없었다.
- **압축 해제 코드 (실행 파일 `0`):** 초기화 `0x060811F0`, 해제 루프 `0x0608124C`. 역어셈블로 확인한 형식:
  - 블록 앞 4바이트(빅엔디언) = **압축 입력 바이트 수**. 입력을 한 바이트 읽을 때마다 줄이고, 0이 되면 멈춘다(출력 크기가 아님).
  - 플래그 바이트는 LSB부터 읽고, 비트 1 = 리터럴 1바이트, 비트 0 = 2바이트 참조 `offset = lo | (hi & 0xF0) << 4`, `길이 = (hi & 0x0F) + 3`.
  - 창 4096바이트, 쓰기 시작 위치 `0xFEE`, 창 `[0, 0xFEE)`만 0으로 초기화한다. `[0xFEE, 0x1000)`에는 이전 해제 때 남은 값이 그대로 있으므로, 재압축기는 아직 쓰지 않은 그 구간을 참조하면 안 된다.
- **타이틀 블록:** `PROLOG.BIN` 오프셋 `0x7900`, 입력 11,438바이트 → 출력 31,868바이트. 실행 파일이 고정 주소 `0x00207900`으로 참조한다(`0x060772F0`, `0x060788FC`). 다음 블록은 `0xA600`에서 시작하고, 사이에 0으로 채워진 78바이트가 있다(쓰이지 않는 공간인지는 미확인).
- **"Yc" 스프라이트 묶음 형식:** `u16 0x5963`, `u16 항목 수`, 항목마다 `u16 폭, u16 높이, u16 속성(0x0080), u16 색 뱅크(0x20xx)`, 이어서 4bpp 텍스처가 순서대로 붙는다. 타이틀 블록 11개 항목이 모두 VRAM 텍스처와 바이트 단위로 일치하고, 합계 길이가 블록 출력 길이와 정확히 같다. 같은 매직이 `PROLOG.BIN` 첫 블록과 `SP*.SPR`에도 있다(해당 파일들의 형식 일치는 미확인).
- **타이틀 묶음 항목:** 0 スーチーパイ♡ 로고 256×96, 1 Ⅱ 96×80, 2 アイドル雀士 128×24, 3·4 저작권 표기, 5 TM, 6 하트 112×112, 7·8 PRESS START 136×24, **9 「最初から始める／続きから始める」 136×48**, 10 별 16×16.
- **디코더 검증:** 이 블록 하나에서 디코더 출력이 게임이 VRAM에 올린 결과와 일치했다(독립 기준). 다른 블록은 아직 검증하지 않았다.

### 3.7 한글 타이틀 로고 적용 (v0.1)

- **빌드:** `tools/khpatch.py build`. 사양은 `assets/title/title_ko.json`(칸 위치·그리는 순서·팔레트는 3.6절 타이틀 화면 관찰값).
- **배치:** 제공 로고를 4방향 연결 요소 단위로 둘로 나눔. 노란 "아이돌 작사"는 "アイドル雀士" 칸(128×24, 노랑·빨강 팔레트)에, 분홍 "스치파이♡2"는 로고 칸(256×96)과 Ⅱ 칸(96×80)에 들어감. 픽셀마다 덮는 칸들 중 색을 가장 잘 표현하는 팔레트의 칸에 배정하고 나머지 칸은 투명. 제공 로고에 ™가 있어 원래 ™ 스프라이트(항목 5)는 비움. 처음에 직사각형으로 나눴을 때 분홍 글자 꼭대기 조각이 노란 쪽에 딸려 가 점이 찍혀서 연결 요소 방식으로 바꿈.
- **압축:** 최적 분할 LZSS. 한글판 블록 11,397바이트(헤더 포함), 원래 블록(11,442바이트)보다 작아 뒤쪽 0 구간은 쓰지 않음.
- **대조군 (압축 기준 C):** 그림을 바꾸지 않고 다시 압축한 디스크(블록 11,129바이트)를 새로 부팅해 타이틀에 들어가면, 게임이 VRAM에 올린 텍스처 11개가 원본과 바이트 단위로 같음.
- **한글판 확인:** 새로 부팅해 오프닝을 건너뛰고 타이틀에 들어가면, VRAM 텍스처 11개가 빌드한 묶음과 바이트 단위로 같고 화면에 한글 로고가 나옴(`work/evidence/title-ko-v2.png`). 원본과 같은 입력 순서로 Start를 누르면 한글판·대조군·원본 모두 메뉴 전환 화면으로 넘어감.
- **확인하지 않은 것:** 오프닝을 끝까지 본 뒤 들어가는 타이틀, 데모 순환 뒤 돌아오는 타이틀, 「最初から／続きから」 선택 화면(항목 9, 아직 일본어), 하트 스프라이트(항목 6)가 쓰이는 장면. 로고 배치·색은 사람 확인 전.

### 3.8 메뉴 그림 글자 (SELECT1.BIN, v0.2)

- **구조 (확인):** `SELECT1.BIN`(442,368바이트) = 앞 `0x0000~0x2FC0` CRAM 이미지(뱅크 b의 팔레트가 오프셋 b×2) + `0x2FC0`의 비압축 "Yc" 묶음 139항목(4bpp 92, 8bpp 47) + 끝 0 채움. 메뉴·난이도·사운드 테스트·스테이지 선택·파트너 선택 화면이 이 파일을 쓴다.
- **분모 (139, 미해결 0):** 글자 항목 58개는 번역 대상, 81개는 근거와 함께 제외(8bpp 캐릭터 그림 47, 빈 틀 8, 숫자 16, 음표 7, 화살표 2, `No.` 1). 목록과 원문 받아쓰기·원본 텍스처 SHA-1은 [`translation/select1.json`](../translation/select1.json).

- **번역:** 58개 모두 초벌(`needs_review`). 사람이 정한 표기(난이도 쉬움/보통/어려움, "~ 선택")는 [`translation/glossary.json`](../translation/glossary.json)에 승인으로, 나머지 이름·용어는 제안으로 기록. 사람 판단이 필요한 항목은 번역 표 `note`에 표시(平和 말장난, ウサちゃん 어감, 곡 제목 번역 방침, ぺこぺこピーにゃんで 의미, 63번 줄임 등).

## 5. 대사 처리 선택지

| 선택지 | 내용 | 비용·위험 |
|---|---|---|
| A. 그림 글자만 | 메뉴·타이틀·이름·소개 카드·대국 표시 등을 한글 그림으로 교체. 음성은 일본어 그대로, 자막 없음 | 가장 현실적. 코드 변경은 그림 형식·압축에 따라 최소 |
| B. A + 자막 추가 | 음성마다 한국어 자막을 화면에 띄움 | 매우 큼: 약 166분(쓰임새 미확인분 포함) 받아쓰기·번역, 음성 재생 지점마다 자막 표시 코드(SH-2 후킹, VDP 표시층, 한글 글꼴) 새로 작성, 타이밍 맞춤 |
| C. A 먼저, B는 나중에 따로 판단 | A로 1차 배포 가능한 결과를 만든 뒤 자막 PoC 한 장면으로 비용을 다시 잼 | A와 같음 + 이후 PoC 비용 |
