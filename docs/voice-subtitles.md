# 음성 자막

대사 음성에 한국어 자막을 붙이는 작업의 기록과 번역 지침.

## 1. 범위 (사람 결정, 프로젝트 소유자 2026-10-04)

- **넣음:** 대국 전 대화(STP/STL/STC/STM/YKM 94개, 약 103분), 벌칙 장면(X70~X73 A/B/C), 파트너 소개·변신(X50~X54), 필살기·소환 연출(X60), 오프닝(PR1A·PR2A·V51A), 쿄코 장면(V71A~V74A), 세실 장면(O51A), 만관 보너스 화면(W47A~W50A), 유키 등장(YOP0·YOP1).
- **뺌:** 대국 중 짧은 호출(X00~X40, V00~V29), 역 이름 호출(Y*), 메뉴 안내·패널 매치 호출(W00~W46).
- **보류:** 시스템 음성 W60~W74·P60A·P61A·V61A·V62A(장면 파일 없이 재생돼 자막을 미리 읽을 시점이 없음), 사운드 테스트 NG집(ZZA~ZZP).
- 이야기 스트림 `2SUTI`~`8ALL`·`1SUTI_SE`는 배경음악이다(받아쓰기 결과가 비어 있음). 처음 조사(`initial-survey.md` 3.3절)의 "이야기 장면 스트림"은 틀린 추정.

그룹과 촉발 파일은 [`assets/subtitle/scenes.json`](../assets/subtitle/scenes.json).

## 2. 번역 지침

### 2.1 파일 형식

음성 하나에 파일 하나: `translation/voice/<음성 이름>.json` (예: `STP001.json`).

```json
{
 "voice": "STP001.AIF",
 "scene": "대국 전 대화 — 피치파이(아리스) 1스테이지, 상대 루미",
 "duration": 81.06,
 "source": "faster-whisper large-v3 받아쓰기 초안, 번역 초안 (사람 검수 전)",
 "lines": [
  {"start": 1.87, "end": 2.85, "speaker": "루미", "ja": "お久しぶり", "ko": "오랜만이야.", "status": "needs_review"}
 ]
}
```

- `start`/`end`: 음성 파일 안의 초. 받아쓰기 시각을 따르고, 긴 구간은 단어 시각(`words`)으로 나눈다. 줄끼리 겹치지 않게, 시간 순서대로.
- `ja`: 원문. 받아쓰기를 문맥으로 고친 줄은 `"asr_uncertain": true`와 `"note"`에 원래 받아쓰기를 남긴다.
- `ko`: 자막. 비우면 그 줄은 화면에 나오지 않는다(신음·웃음만 있는 줄 등).
- `speaker`: 말하는 사람(추정). 화면에는 나오지 않고 검수용.
- `status`: `needs_review`(초벌) → `needs_human_review`(2차 검수 통과) → `distribution_eligible`(사람 승인).

### 2.2 화면 제약

- 자막은 화면 아래(y 200~231)에 최대 두 줄. 한 줄 폭 304픽셀 = 나눔스퀘어라운드 14픽셀로 한글 약 20자. 두 줄을 넘는 문장은 빌드가 거부한다 → 줄을 시간으로 나눠라.
- 한 줄은 길어도 6초, 짧아도 1초 남짓. 빠르게 주고받는 대사는 받아쓰기 구간 그대로 둔다.
- 쓸 수 있는 글자: 한글, 숫자, 영문, 기본 문장부호(`.,!?~…·'"()-`). 일본어 가나·한자, 하트(♡) 같은 기호는 쓰지 않는다.

### 2.3 받아쓰기 다루기

- 대국 전 대화는 두 가지 받아쓰기가 있다: `work/asr/st/`(VAD 있음, 대사를 빠뜨리기도 함), `work/asr/st_novad/`(VAD 없음, 빠진 대사를 잡지만 환각이 섞임). 둘을 맞대어 실제 대사를 정한다.
- 환각으로 보이는 것은 버린다: 「ご視聴ありがとうございました」, 「次回予告」, 같은 말이 끝없이 반복되는 구간, 음성 길이를 넘는 시각.
- 잘못 들은 말은 문맥으로 고친다. 예: 「スーチーパイ健三」→「スーチーパイ見参」, 「熱気とした」→「れっきとした」, 「数値」→「スーチー」, 「アイマン」→「倍満」 등.
- 이름 받아쓰기는 용어집 표기로: 아리스(ありす), 츠카사, 사나에, 루미, 밀크, 유키, 쿄코, 레이카, 세실, 시호, 에리카, 리에, 미유리, 마이, 사유리.

- 성적 묘사는 원문 수위를 그대로 옮긴다(더하지도 빼지도 않음).

## 3. 기술 기록

### 3.1 구조

- **실행 파일 `0`** (같은 크기로 교체): `0x060045EC`의 수직 동기 대기 함수(128바이트)를 같은 동작의 40바이트로 줄이고, 남은 88바이트에 연결 코드를 둔다. 파일 읽기 함수 `0x06006874`를 가리키는 리터럴 66곳이 모두 연결 코드를 가리킨다. 연결 코드는 첫 호출 때 `SUB.BIN`을 `0x060F6800`에 읽고(BSS 끝 `0x060F6518` 뒤, 이 구역을 쓰는 코드 없음 — `malloc`/`sbrk`도 안 쓰임), 캐시를 비운 뒤 `SUB.BIN`의 읽기 훅으로 넘긴다. `SUB.BIN`이 없으면 원래 함수로 간다.
- **`SUB.BIN`** = 코드(≤ 0x1400, `tools/subtitle/`, WSL의 `sh4-linux-gnu-gcc -Os`) + 색인(≤ 0x1400, 빌드가 붙임). 실행 중에 훅을 건다: 음성 재생 `0x06055C80`(리터럴 66곳)과 그 감싸개 `0x06055E88`(9곳), 수직 동기 콜백의 `0x0608C9E4` 호출(SCL 프레임 끝·VDP2 레지스터 업로드) 뒤.
- **`SUBDAT.BIN`**: 그룹(음성 이름, 줄, 글리프 2bpp)마다 게임과 같은 LZSS(`tools/suchie2/lzss.py`)로 압축해 이어 붙인 파일. 913KB → 446KB(218섹터). 색인에 각 그룹의 바이트 위치·압축/원래 크기가 있다.
- **그룹 읽기 시점**: 게임이 장면 파일(촉발 파일: `P000.MTS`, `DTRM10.MSX`, `SPALICE.MSX`, `PROLOG.BIN` …)을 읽을 때, 파일 읽기 훅 안에서 그 그룹을 먼저 읽는다(게임의 파일 읽기와 같은 순서: 음성 정지 → GFS 이름 찾기 → `GFS_Load`). 그룹이 걸친 섹터를 데이터 영역(`0x060F9000`~`0x060FE800`) 끝으로 읽고 앞쪽으로 푼다(쓰기 위치가 읽기 위치를 넘지 않는지 빌드가 시뮬레이션으로 확인). 같은 파일이 여러 그룹의 촉발 파일이면(공용 애니메이션 등) 이미 올라온 그룹이 그 파일을 가지고 있을 때 다시 읽지 않는다.
- **장면 도중 읽기 금지**: 벌칙 장면이 도는 중(음성 재생 시점)에 그룹을 읽으면 VDP1 그리기 끝 인터럽트를 놓쳐 프레임 대기(`0x0608C98C`)가 끝나지 않고 멈춘다. 음성 재생 훅은 이미 올라온 그룹에서 이름만 찾는다.
- **디스크**: 두 파일은 트랙 1 마지막 파일(GEND, LBA 270643까지) 뒤 빈 섹터(300개)에 쓴다(`SUB.BIN` 270643~, `SUBDAT.BIN` 270648~). 파일 사이 빈 곳은 없다. 루트 디렉터리는 이름 순으로 다시 짠다(23섹터 유지; 원래 마스터링 도구는 섹터를 꽉 채우지 않음 — 같은 규칙으로 다시 짜면 원본과 바이트 단위로 같음). GFS 디렉터리 표 용량 1,200칸(사용 1,032 → 1,034).
- **메모리**: `0x060F6800` 코드 / `0x060F7C00` 색인 / `0x060F9000` 그룹 데이터(≤ 0x5800) / `0x060FEC00` NBG3 셀 버퍼(160칸) ~ `0x06100000`.

### 3.2 시각

- 음성은 SEGA PCM 라이브러리가 사운드 RAM `0x7C000`의 8192샘플 고리로 흘린다. 그 주소를 재생하는 슬롯이 꺼졌다 켜지는 수직 동기를 자막 기준(0초)으로 삼는다(재생 호출 15~29 프레임 뒤). 180프레임 안에 못 보면 호출 + 30.
- 수직 동기 카운터 `0x060BE720`(콜백에서 1씩 증가), 59.826Hz. 줄은 음성 구간 0.1초 전에 뜨고 끝난 뒤 0.6초(다음 줄이 먼저 오면 그때까지, 최소 1초) 남는다.

### 3.3 글자 면

- 음성이 있는 장면은 NBG0/NBG1 비트맵과 VDP1 스프라이트로 그려지고 NBG2·NBG3는 꺼져 있다. 자막은 NBG3(4bpp 1×1 셀, 우선순위 7)의 맵 25~28행(y 200~231)에 최대 두 줄, 나눔스퀘어라운드 ExtraBold 14픽셀, 흰 글자 + 회색 가장자리 + 검은 테두리.
- 장면마다 VRAM 배치가 달라, 실행 중에 SCL 라이브러리의 레지스터 사본(`0x060B4E30`+레지스터; `0xE0`~ 은 `0x060B5D2C`, `0xFE` 건너뜀 — 세이브 스테이트 3개에서 칩 레지스터와 대조)을 읽어 고른다.
  1. 16KB 블록(`0x7C000`, `0x3C000`, `0x5C000`, `0x1C000` 순): 먼저 보이는 비트맵 줄과 겹치지 않고 비어 있는 블록, 없으면 켜진 비트맵 어디와도 겹치지 않는 블록(이전 장면이 남긴 데이터는 덮어씀, 줄이 끝나면 0으로 지움).
  2. 그 뱅크의 접근 패턴에서 이웃한 빈 슬롯 두 개(F, 비트맵 면의 이름 읽기, 꺼진 면의 읽기)를 NBG3 이름·문자 읽기로.
  3. 비어 있는 CRAM 팔레트 행(13, 12, 14, 15, 4~7 순).
  NBG2·NBG3·회전면을 쓰거나 셀 면이 켜진 화면(대국 화면 등), 줄 스크롤·라인 컬러 표를 쓰는 화면에는 띄우지 않는다.
- 스프라이트는 우선순위가 같으면 NBG보다 위라서, 줄이 떠 있는 동안 스프라이트 우선순위 7을 6으로 낮춘다(두 비트맵 면이 6 이하일 때만 — 장면 안 순서는 그대로).
- 레지스터는 쓰기 전용이고 라이브러리가 사본에서 다시 올리므로, 올린 직후 NBG3 관련 필드를 덮어쓰고 줄이 끝나면 사본 값으로 되돌린다.

### 3.4 확인 (Mednafen 1.32, 2026-10-04)

| 장면 | 화면 구성 | 결과 |
|---|---|---|
| 오프닝(PR2A·V51A) | 비트맵 | 줄이 대사에 맞춰 나옴 |
| 파트너 소개 내레이션(B50A) | 비트맵 | 나옴 |
| 변신(B51A)과 소개(B52A, 얼굴 창) | NBG0 256색 512×512, VRAM 전부 이전 데이터 | 둘째 규칙(비트맵 밖 블록)으로 나옴 |
| 1스테이지 대국 전 대화(STP001, 전체 화면) | NBG0 32K색 | 나옴, 대국 화면 정상 |
| 2스테이지 대국 전 대화(STP002, 레터박스) | NBG0+NBG1 | 아래 검은 띠에 나옴, 두 줄일 때 윗줄이 얼굴 창 위에 그려짐 |
| 루미 벌칙 장면(Q70B) | NBG0+NBG1 256색 | 나옴, 장면 정상 진행 |

- 대국 화면(NBG3 사용)·메뉴·카드 화면은 자막 조건에 맞지 않아 아무것도 바꾸지 않는다.
- 아직 확인하지 않은 것: 2스테이지 이후의 벌칙·대화 장면 전부, 필살기 연출, 보너스 화면, 유키 경로, 실기. 음성과 자막의 어긋남은 녹음으로 재지 않았다(기준은 Steam Hearts에서 같은 방식으로 잰 0.08초).

### 3.5 개발 도구 (`work/`, 커밋 안 함)

- `work/tools/drive.py`: Mednafen 창에 키 보내기(스캔 코드), 화면 저장, 세이브 스테이트. 창이 앞에 없으면 보내지 않는다.
- `work/tools/mcsedit.py`, `inject.py`, `prep_state.sh`, `quicktest.sh`: 세이브 스테이트 RAM에 새 `SUB.BIN`을 넣고 CPU 캐시 태그를 무효화, GFS 디렉터리 표를 새 디스크에 맞춰 고친 뒤 이어서 시험.
- `work/subdisc.py`: 빌드된 디스크에 자막만 다시 얹는 빠른 시험 디스크.
- 승리 장면 만들기: 손패 배열 `0x060BA99E`(u16 14칸, 0~33)와 패산 `0x060BA9FA`(136칸)를 고쳐 쯔모(B → 쯔모 선택).
- 받아쓰기: `work/tools/asr.py`(faster-whisper large-v3, `NOVAD=1`이면 음성 구간 검출 끔).
